## Checking Availability Programmatically

Use the capabilities endpoint to check what features are available for a specific user based on their country of residence:

```
GET /api/v2/user
```

The response includes a `capabilities` array with entries such as:

| Capability | Description |
|---|---|
| `SepaAccount` | SEPA bank account (EUR) |
| `AchAccount` | ACH bank account (USD) |
| `VisaVirtualCard` | Virtual Visa card |
| `VisaPlasticCard` | Physical Visa card |

Status values:

- `Active` -- Available and ready to use
- `NotFulfilled` -- Requires additional verification (e.g., higher KYC level)
- `NotAvailable` -- Not available for the user's country of residence

## KYC Requirements by Region

Bank account access and card issuance require different KYC levels depending on the user's country of residence:

| KYC Level | Capabilities | Typical Requirements |
|---|---|---|
| **Level 0** | View-only, no transactions | Email verification |
| **Level 1** | Crypto deposits and limited transfers | Government ID + selfie verification |
| **Level 2** | Full banking (SEPA/ACH), card issuance | Address verification + enhanced due diligence |
| **Level 3** | High-value operations | Source of funds documentation |

Specific requirements vary by country and are returned by the `GET /api/v1/validation/rules` endpoint.
